# AWS Emulator 1.0.367 compatibility audit

Audited tag: `v1.0.367`, commit `129a3db1945ce884e6d0341e4d77e19b8efc9667`.
Previous audit: `v1.0.322`, commit `7753983c6e495ec3612695b1336bf4936fc7b7fd`.
This records the source review and regression coverage for the upgrade. It does
not replace the approving PR review required on `main`.

## CloudFormation dispatch review

The catalogue follows executable provisioning dispatch, rather than the broader
resource-name inventory or names mentioned in comments:

- [`provisioner_for`](https://github.com/aws/aws-emulator/blob/129a3db1945ce884e6d0341e4d77e19b8efc9667/services/service-com-amazonaws-cloudformation-cloudformation/src/state/provisioner.rs#L1026): 147 exact type names, including aliases sharing an implementation. The default arm returns `None`.
- [`owner_for`](https://github.com/aws/aws-emulator/blob/129a3db1945ce884e6d0341e4d77e19b8efc9667/services/service-com-amazonaws-cloudformation-cloudformation/src/state/provisioning.rs#L992): 65 additional exact names from direct comparisons and dedicated `kind_of` dispatch. API Gateway delegates to both `access_control` and `request_validation`; both branches are included.
- [`Owner::create`](https://github.com/aws/aws-emulator/blob/129a3db1945ce884e6d0341e4d77e19b8efc9667/services/service-com-amazonaws-cloudformation-cloudformation/src/state/provisioning/owner.rs) and the new catalogue create arms route these types into their owning service operations. New dedicated families include Cognito user pools, ECS task definitions, CloudFront, ELBv2, Lambda asynchronous invocation configuration, and Secrets Manager policies/rotation.

The result is **212 native names**, with **42 additions and no removals** compared
with the previous 170-name catalogue. Nested `AWS::CloudFormation::Stack` is kept
in the source inventory but rejected by the template guard, leaving 211 accepted
native types. `AWS::CDK::Metadata` and the separately reviewed signal behavior of
`AWS::CloudFormation::WaitCondition` remain explicit exceptions. Wait-condition
handles, transforms/macros, nested templates, custom providers, unknown types,
and declaration-only types remain blocked before any connection or submission.

The catalogue establishes that a create reaches provisioning. It does not certify
every property, update/replacement path, or service data plane. No automatic
catalogue generation or version bypass was added to the upgrade workflow.

One observed upstream limit: changing `UserPoolName` in a stack containing an app
client and resource server that reference that pool entered
`UPDATE_ROLLBACK_IN_PROGRESS`, with those dependent resources failing to update.
The plugin correctly failed the deployment. The added lifecycle regression keeps
the pool name stable and verifies an app-client name update, then deletion of the
stack. Pool renaming with dependent resources is not certified by this audit.

## Compatibility fixes and regression coverage

- DynamoDB now rejects explicitly empty optional index lists. `CreateDynamoDbTableTask` omits absent global/local indexes and still submits configured indexes. Existing schema/drift validation is retained. The DynamoDB and data-scenario integration suites cover creation, reuse, indexes, item operations, and configuration-cache reuse.
- [Cognito token signing](https://github.com/aws/aws-emulator/blob/129a3db1945ce884e6d0341e4d77e19b8efc9667/services/service-com-amazonaws-cognitoidentityprovider-awscognitoidentityproviderservice/src/state/tokens.rs#L190) uses RS256. The local Spring example explicitly trusts RS256 and retains issuer, expiry, access-token, client-id, group, signature, and TLS checks. Its integration suite checks password/refresh flows and rejects ID tokens, other-client tokens, and tampering.
- [SES v2 template listing](https://github.com/aws/aws-emulator/blob/129a3db1945ce884e6d0341e4d77e19b8efc9667/services/service-com-amazonaws-sesv2-simpleemailservice-v2/src/ops/list_email_templates.rs) is now implemented. Report integration tests require complete SES metadata (including templates), no template contents, and successful strict reports. Unsupported-operation behavior remains covered by the functional/unit suites.
- The containerized test's Docker relay now preserves the response after a request half-close. Previously `docker exec` could lose output/status and appear ready before generated connection files existed. The existing containerized-runtime suite covers real remote Docker, both default/named runtimes, cache reuse, and cleanup on failure. Runtime credential and TLS validation are unchanged.
- Windows CI also exposed a process-cleanup race: forced termination is asynchronous. The command runner now waits up to five seconds for the child to exit before returning, preserving interruption and allowing log/workspace deletion. The archive regression explicitly deletes its log after a timeout.
- The PowerShell export regression allows up to 60 seconds for cold process startup on busy CI hosts, reaps the child on timeout/interruption, and includes diagnostics on timeout. Its credential-removal and literal-path assertions are retained.
- Windows functional fixtures use TestKit's managed cache directory to avoid daemon-held temporary-directory locks. Framework cache assertions run after GraalVM creates its first-use shared access-filter file, removing test-order dependence in both functional and Docker suites while still requiring cache reuse. Shared-runtime setup failures use a tracked Gradle property rather than depending on immediate filesystem-watcher delivery after editing a build script.
- CloudFormation tests retain rejection before connection (including false conditions and external runtimes), parser safeguards, and version mismatch failures. The Docker suite checks S3/SQS/DynamoDB reads and writes, no-op/update/replacement/deletion, and failure cleanup. A new test creates, describes, updates, and deletes Cognito pools, app clients, and resource servers through CloudFormation and verifies them through Cognito APIs.

Run `./gradlew build` and `./gradlew dockerTest`. The PR's required **CloudFormation
audit** and **Emulator compatibility** checks report the cross-platform matrix;
manual approval is still required before merging.
