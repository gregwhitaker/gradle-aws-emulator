= S3 Buckets & Objects
include::_partials/attributes.adoc[]
:description: Create and configure S3 buckets, policies, versioning, and notifications; upload, list, and download objects.

The S3 module supplies typed tasks for buckets and objects. All task types live in `io.github.gregwhitaker.awsemulator.aws.s3` and use the *AWS Emulator - S3* task group. Each task starts the selected emulator on demand and waits until it is ready.

toc::[]

== Register Resource Tasks

Make your test task depend on provisioning, then opt that same consumer into the emulator. Provisioning tasks default to the shared managed instance.

=== Kotlin DSL

[source,kotlin]
----
import io.github.gregwhitaker.awsemulator.aws.s3.CreateS3BucketTask

plugins {
    java
    id("io.github.gregwhitaker.aws-emulator")
}

val createBucket = tasks.register<CreateS3BucketTask>("createTestBucket") {
    bucketName.set("application-test-data")
}
val tests = tasks.named<Test>("test") {
    dependsOn(createBucket)
}
awsEmulator {
    useWith(tests)
}
----

=== Groovy DSL

[source,groovy]
----
import io.github.gregwhitaker.awsemulator.aws.s3.CreateS3BucketTask

plugins {
    id 'java'
    id 'io.github.gregwhitaker.aws-emulator'
}

def createBucket = tasks.register('createTestBucket', CreateS3BucketTask) {
    bucketName.set('application-test-data')
}
def tests = tasks.named('test') {
    dependsOn(createBucket)
}
awsEmulator {
    useWith(tests)
}
----

NOTE: A managed provisioning task invoked alone creates resources that disappear when the build finishes. To keep resources available for a development session, select xref:lifecycle.adoc#provision-development-resources[`DEVELOPMENT` mode].

== Task Properties

All properties use Gradle's lazy property API.

[cols="1,1,2",options="header"]
|===
|Task type |Required |Optional
|`CreateS3BucketTask` |`bucketName` |`mode`, `apiCallTimeoutSeconds`
|`CreateS3BucketsTask` |`buckets` |`mode`, `apiCallTimeoutSeconds`
|`ListS3BucketsTask` |None |`mode`, `apiCallTimeoutSeconds`
|`PurgeS3BucketsTask` |`buckets` |`mode`, `apiCallTimeoutSeconds`
|`DeleteS3BucketsTask` |`buckets` |`force` (default `false`), `mode`, `apiCallTimeoutSeconds`
|`PutS3BucketPolicyTask` |`bucketName`, exactly one of `policy` or `policyFile` |`mode`, `apiCallTimeoutSeconds`
|`DeleteS3BucketPolicyTask` |`bucketName` |`mode`, `apiCallTimeoutSeconds`
|`PutS3BucketVersioningTask` |`bucketName`, `status` |`mode`, `apiCallTimeoutSeconds`
|`PutS3BucketNotificationConfigurationTask` |`bucketName`, `notificationConfiguration` |`mode`, `apiCallTimeoutSeconds`
|`UploadS3ObjectTask` |`bucketName`, `objectKey`, `sourceFile` |`contentType`, `metadata`, `mode`, `apiCallTimeoutSeconds`
|`UploadS3DirectoryTask` |`bucketName`, `sourceDirectory` |`prefix`, `contentTypes`, `metadata`, `mode`, `apiCallTimeoutSeconds`
|`ListS3ObjectsTask` |`bucketName` |`prefix`, `mode`, `apiCallTimeoutSeconds`
|`DownloadS3ObjectTask` |`bucketName`, `objectKey`, `outputFile` |`mode`, `apiCallTimeoutSeconds`
|===

[cols="1,1,3",options="header"]
|===
|Shared property |Default |Meaning
|`mode` |`awsEmulator.defaultMode` for custom instances (initially `MANAGED`) |Select the build-owned runtime or the persistent `DEVELOPMENT` runtime. The module convenience tasks default to `DEVELOPMENT`.
|`runtimeName` |`default` |Select a declared named runtime. Its name and lifecycle mode must match the consumer; see xref:named-runtimes.adoc[named runtimes].
|`apiCallTimeoutSeconds` |`30` |Positive timeout for each SDK operation, including retries.
|===

Provisioning tasks always execute and are never restored from the build cache because they operate on live emulator state. The plugin supplies its own SDK dependencies for these tasks; the application declares its own dependencies.

== S3 Bucket Behavior

`CreateS3BucketTask` and `CreateS3BucketsTask` create general-purpose buckets in `awsEmulator.region`. For `us-east-1`, it omits the location constraint; for other regions, it sends the configured region.

If an accessible bucket already exists, the task reuses it without another `CreateBucket` call. Its objects and configuration remain intact. A region mismatch reported by `HeadBucket` fails the task.

These creation tasks do not configure directory buckets or access points. Use the configuration tasks below for policies, versioning, and notifications, and the object tasks to seed bucket contents.

API: link:api/io/github/gregwhitaker/awsemulator/aws/s3/CreateS3BucketTask.html[CreateS3BucketTask].

== Bulk Creation

[source,kotlin]
----
import io.github.gregwhitaker.awsemulator.aws.s3.CreateS3BucketsTask

val createBuckets = tasks.register<CreateS3BucketsTask>("createTestBuckets") {
    buckets.set(listOf("application-data", "application-uploads"))
}
----

`buckets` is a `ListProperty<String>`. Bulk creation uses the singular task's region and reuse checks. All names are validated before starting the emulator. Duplicate names are processed once.

API: link:api/io/github/gregwhitaker/awsemulator/aws/s3/CreateS3BucketsTask.html[CreateS3BucketsTask].

== Bucket Policies And Versioning

Configure an existing bucket after its creation task. Configuration tasks do not create a missing bucket. They use the selected runtime and mode, always execute against live state, and close their SDK clients after use.

[source,kotlin]
----
import io.github.gregwhitaker.awsemulator.aws.s3.*
import software.amazon.awssdk.services.s3.model.BucketVersioningStatus
import io.github.gregwhitaker.awsemulator.model.EmulatorMode

val policy = tasks.register<PutS3BucketPolicyTask>("configureBucketPolicy") {
    dependsOn(createBucket)
    bucketName.set(createBucket.flatMap { it.bucketName })
    policyFile.set(layout.projectDirectory.file("fixtures/bucket-policy.json"))
}
val versioning = tasks.register<PutS3BucketVersioningTask>("versionBucket") {
    dependsOn(createBucket)
    bucketName.set(createBucket.flatMap { it.bucketName })
    status.set(BucketVersioningStatus.ENABLED)
}
awsEmulator { useWith(tasks.named<Test>("test"), EmulatorMode.MANAGED, policy, versioning) }
----

`PutS3BucketPolicyTask` accepts exactly one of inline `policy` (`Property<String>`) or `policyFile` (`RegularFileProperty`). Files are UTF-8 and read during execution, including on configuration-cache reuse. Both forms accept a JSON object of at most 20 KiB. Malformed JSON, duplicate keys, and trailing JSON documents fail before connecting; diagnostics omit policy values. Policy semantics are validated by the emulator.

The https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutBucketPolicy.html[policy operation] replaces the entire policy; it does not merge statements. For example, `fixtures/bucket-policy.json` can grant object reads:

[source,json]
----
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"AWS": "arn:aws:iam::000000000000:root"},
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::application-test-data/*"
  }]
}
----

Match the resource ARN to your bucket and the principal to your account. This task preserves S3 Block Public Access settings; public policies can be rejected by the emulator. `DeleteS3BucketPolicyTask` removes only the policy and succeeds when the existing bucket has no policy. A missing bucket or service error fails the task.

`PutS3BucketVersioningTask.status` is a required `Property<BucketVersioningStatus>` accepting `ENABLED` or `SUSPENDED`, without a default. Suspension retains existing versions; it does not return a bucket to its original unversioned state. The task leaves MFA Delete unspecified and exposes no MFA settings. See https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutBucketVersioning.html[versioning behavior].

Register configuration tasks explicitly; the module registers only the policy-deletion convenience command. The registered tasks above also accept command-line overrides:

[source,shell]
----
./gradlew configureBucketPolicy --policyFile=fixtures/bucket-policy.json
./gradlew versionBucket --status=SUSPENDED
./gradlew deleteS3BucketPolicy --bucketName=application-test-data
----

The first two commands use their configured mode, initially `MANAGED`. For persistent configuration, select `DEVELOPMENT` for both the configuration task and its bucket-creation prerequisites; setting `awsEmulator.defaultMode` on the build covers custom tasks together. The deletion convenience command defaults to `DEVELOPMENT`.

API: link:api/io/github/gregwhitaker/awsemulator/aws/s3/PutS3BucketPolicyTask.html[PutS3BucketPolicyTask], link:api/io/github/gregwhitaker/awsemulator/aws/s3/DeleteS3BucketPolicyTask.html[DeleteS3BucketPolicyTask], link:api/io/github/gregwhitaker/awsemulator/aws/s3/PutS3BucketVersioningTask.html[PutS3BucketVersioningTask].

== Bucket Notifications

`PutS3BucketNotificationConfigurationTask.notificationConfiguration` is a required `Property<NotificationConfiguration>` using the AWS SDK v2 model. It accepts queue, topic, Lambda function, and EventBridge configurations, including SDK prefix/suffix filters. There is no default configuration.

For a standard SQS destination:

[source,kotlin]
----
import software.amazon.awssdk.services.s3.model.Event
import software.amazon.awssdk.services.s3.model.NotificationConfiguration
import software.amazon.awssdk.services.s3.model.QueueConfiguration
import io.github.gregwhitaker.awsemulator.aws.s3.PutS3BucketNotificationConfigurationTask
import io.github.gregwhitaker.awsemulator.model.EmulatorMode

val notifications = tasks.register<PutS3BucketNotificationConfigurationTask>("notifyUploads") {
    dependsOn(createBucket, createNotificationQueue)
    bucketName.set(createBucket.flatMap { it.bucketName })
    notificationConfiguration.set(NotificationConfiguration.builder().queueConfigurations(
        QueueConfiguration.builder().id("uploads")
            .queueArn("arn:aws:sqs:us-east-1:000000000000:application-upload-events")
            .events(Event.S3_OBJECT_CREATED).build()).build())
}
awsEmulator { useWith(tasks.named<Test>("test"), EmulatorMode.MANAGED, notifications) }
----

`createNotificationQueue` must provision that queue with an SQS resource policy allowing `s3.amazonaws.com` to perform `sqs:SendMessage`, restricted to the source bucket ARN. Match destination ARNs to the actual account and region. The link:{repo-url}/tree/main/examples/basic[basic example] provides the full queue policy and verifies delivery with the pinned emulator's account `000000000000`. SNS destinations similarly need publishing permission, and Lambda destinations need invocation permission. This task does not create destinations, modify their policies, or bypass destination validation. Direct SQS and SNS FIFO destinations are rejected; use standard destinations.

The https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutBucketNotificationConfiguration.html[notification operation] replaces the *entire* configuration, including destinations not mentioned in the new value. To remove all notifications, explicitly supply `NotificationConfiguration.builder().build()`. To enable EventBridge delivery, include `EventBridgeConfiguration.builder().build()` through the SDK builder's `eventBridgeConfiguration(...)` method. Do not register competing configuration tasks for the same bucket unless their execution order is explicit.

Each destination requires an ARN for its service and at least one recognized S3 event. Supplied IDs must be nonblank and unique across destinations. Filters allow at most one prefix and one suffix, each with a value. Structural validation occurs before connecting; destination permissions, filter overlap, and other service constraints are checked by the emulator. Docker integration tests verify SQS object-created delivery; availability and fidelity of other destination workflows depend on the emulator release.

The three `PutS3Bucket*` task types are setup tasks and participate in resource sets and Spring Boot automatic setup discovery. Deletion tasks are excluded from automatic setup. Groovy DSL uses the same SDK builders and properties with `tasks.register('notifyUploads', PutS3BucketNotificationConfigurationTask) { ... }`.

API: link:api/io/github/gregwhitaker/awsemulator/aws/s3/PutS3BucketNotificationConfigurationTask.html[PutS3BucketNotificationConfigurationTask].

== Upload And Inspect Objects

Object tasks require an existing bucket. Use the bucket task from the registration example as a dependency:

[source,kotlin]
----
import io.github.gregwhitaker.awsemulator.aws.s3.UploadS3DirectoryTask

val uploadAssets = tasks.register<UploadS3DirectoryTask>("uploadTestAssets") {
    dependsOn(createBucket)
    bucketName.set(createBucket.flatMap { it.bucketName })
    sourceDirectory.set(layout.projectDirectory.dir("fixtures/assets"))
    prefix.set("assets")
}
tasks.named<Test>("test") {
    dependsOn(uploadAssets)
}
----

`UploadS3DirectoryTask` preserves relative paths under the configured prefix. `UploadS3ObjectTask` uploads one file to an explicit object key. Uploads replace matching keys and preserve other objects; they do not synchronize deletions.

`ListS3ObjectsTask` follows all response pages and prints object keys and sizes. `DownloadS3ObjectTask` writes to an explicit `outputFile`, replacing it only after the full download succeeds. Object tasks execute again on subsequent builds, including configuration-cache reuse.

See xref:scenarios.adoc#upload-and-inspect-s3-objects[S3 data fixtures] for content types, metadata, directory handling, and development datasets.

API: link:api/io/github/gregwhitaker/awsemulator/aws/s3/UploadS3ObjectTask.html[UploadS3ObjectTask], link:api/io/github/gregwhitaker/awsemulator/aws/s3/UploadS3DirectoryTask.html[UploadS3DirectoryTask], link:api/io/github/gregwhitaker/awsemulator/aws/s3/ListS3ObjectsTask.html[ListS3ObjectsTask], link:api/io/github/gregwhitaker/awsemulator/aws/s3/DownloadS3ObjectTask.html[DownloadS3ObjectTask].

== Module Convenience Tasks

The S3 module registers these tasks in the *AWS Emulator - S3* group. They use the persistent development emulator by default:

[cols="1,2",options="header"]
|===
|Task |CLI options
|`listS3Buckets` |None required
|`listS3Objects` |`--bucketName=application-data`, optional `--prefix=assets/`
|`purgeS3Buckets` |`--buckets=one,two`
|`deleteS3Buckets` |`--buckets=one,two`, optional `--force`
|`deleteS3BucketPolicy` |`--bucketName=application-data`
|===

Every resource task accepts `--mode=MANAGED` or `--mode=DEVELOPMENT` and `--runtime <name>`. Custom instances inherit `awsEmulator.defaultMode`, initially `MANAGED`. Ensure provisioning and consuming tasks select the same runtime name and mode.

[source,shell]
----
./gradlew listS3Buckets
./gradlew listS3Objects --bucketName=application-data --prefix=assets/
./gradlew purgeS3Buckets --buckets=application-data
./gradlew deleteS3Buckets --buckets=application-data --force
----

=== Listing And Cleanup

S3 listing follows all response pages and prints bucket names and creation dates. Purging retains the bucket but removes objects, historical versions, and delete markers, including when versioning is suspended. The task checks individual deletion errors even when the service accepts the batch. Deletion requires an empty bucket unless `force` is `true`; an already absent bucket succeeds. Purging and deleting require explicit bucket names.

API: link:api/io/github/gregwhitaker/awsemulator/aws/s3/ListS3BucketsTask.html[ListS3BucketsTask], link:api/io/github/gregwhitaker/awsemulator/aws/s3/ListS3ObjectsTask.html[ListS3ObjectsTask], link:api/io/github/gregwhitaker/awsemulator/aws/s3/PurgeS3BucketsTask.html[PurgeS3BucketsTask], link:api/io/github/gregwhitaker/awsemulator/aws/s3/DeleteS3BucketsTask.html[DeleteS3BucketsTask].

== SDK Connection Isolation

Provisioning clients use explicit emulator endpoints, regions, generated credentials, and per-client TLS trust. They bypass inherited proxy settings. They do not modify the Gradle daemon's credentials or global SSL configuration, and they do not require the AWS CLI.
