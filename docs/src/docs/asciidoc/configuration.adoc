= Configuration
include::_partials/attributes.adoc[]
:description: Complete configuration reference and defaults for the awsEmulator Gradle extension.

Configure the `awsEmulator` extension using Gradle's lazy properties. Top-level runtime settings configure the reserved `default` runtime's managed and development instances; restart an existing development instance after changing runtime settings.

toc::[]

== Extension reference

[cols="1,1,3",options="header"]
|===
|Property |Default |Meaning
|`emulatorVersion` |`1.0.322` |Pinned AWS Emulator package used when building an image.
|`image` |Unset |Use this Docker image instead of building one. Pull it if it is missing locally.
|`platform` |`auto` |Detect the Docker engine architecture, or select `linux/amd64` or `linux/arm64`.
|`port` |`0` |Automatically select an available local endpoint port; also the container port with `DIRECT`. Set a nonzero value for a fixed port. Also configurable with `-PawsEmulator.port=...`.
|`region` |`us-east-1` |Region passed to consuming SDKs and resource provisioning.
|`telemetryEnabled` |`false` |Explicitly enable the emulator's AWS telemetry.
|`dockerExecutable` |`docker` |Docker command name or absolute executable path.
|`docker.host` |Empty |Docker daemon address passed as `--host`, such as `ssh://builder@example.com`. Mutually exclusive with `docker.context`.
|`docker.context` |Empty |Docker context name passed as `--context`. With both selection properties empty, Docker uses its existing context/environment.
|`docker.transport` |`DockerTransport.DIRECT` |`DIRECT` uses local port publication and bind mounts. `TUNNEL` supports managed runtimes in containerized CI and on remote engines; see xref:remote-docker.adoc[remote Docker].
|`memoryLimit` |`2g` |Container memory limit. Swap is capped at the same total.
|`startupTimeoutSeconds` |`60` |HTTPS readiness deadline after the container starts, or while connecting to an external emulator.
|`commandTimeoutSeconds` |`60` |Timeout for each normal Docker command.
|`buildTimeoutSeconds` |`600` |Timeout for an image build or pull.
|`workingDirectory` |`.aws-emulator` in the project |Generated Dockerfiles, locks, and isolated runtime homes.
|`runtimes` |Empty container |Independent named runtimes. Common settings inherit from this extension, with automatic ports, separate working directories, and independently configured external connections. See xref:named-runtimes.adoc[named runtimes].
|`defaultScenario` |`default` |Registered scenario selected by `seedAwsEmulator` and `resetAwsEmulator`. Override with `-PawsEmulator.scenario=<name>`.
|`scenarios` |Empty container |Named development scenarios with resource provisioning and ordered fixture tasks. See xref:scenarios.adoc[Data fixtures & development scenarios].
|`external` |Disabled |Connect to an already-running emulator using `endpoint`, `credentialsFile`, and `certificateFile`. Configuring the block enables it; see xref:external-emulators.adoc[existing emulators].
|===

The `useWith(taskProvider)` method accepts an existing `Test`, `JavaExec`, or `Exec` task provider. See xref:testing.adoc[tests and process execution] for lifecycle and caching behavior. When `external.enabled` is true, both runtime modes use the external connection; Docker settings are ignored and lifecycle commands are rejected.

The `useSharedRuntime(ownerProject, resourceSets...)` method selects an absolute project path in this build and optional resource-set names from that owner. Its runtime settings and working directory replace the consumer's runtime settings. See xref:shared-runtimes.adoc[sharing across projects] for ownership rules and examples.

API: link:api/io/github/gregwhitaker/awsemulator/emulator/AwsEmulatorExtension.html[AwsEmulatorExtension].

== Configure a project

.Kotlin DSL
[source,kotlin]
----
awsEmulator {
    region.set("us-west-2")
    memoryLimit.set("3g")
    startupTimeoutSeconds.set(120)
    buildTimeoutSeconds.set(900)
    workingDirectory.set(layout.projectDirectory.dir(".aws-emulator"))
    useWith(tasks.named<Test>("test"))
}
----

.Groovy DSL
[source,groovy]
----
awsEmulator {
    region.set('us-west-2')
    memoryLimit.set('3g')
    startupTimeoutSeconds.set(120)
    buildTimeoutSeconds.set(900)
    workingDirectory.set(layout.projectDirectory.dir('.aws-emulator'))
    useWith(tasks.named('test'))
}
----

Managed and development instances select available ports by default. The default runtime reads `awsEmulator.port`, so `-PawsEmulator.port=9297` requests a fixed port without changing the build script. An explicit `port.set(...)` replaces that convention and takes precedence over the command-line property. Named runtimes select their own ports independently.

== Image and platform overrides

Leave `image` unset to build the pinned AWS package. Set it only for an image whose entrypoint runs AWS Emulator, binds `0.0.0.0`, and accepts the emulator's normal CLI flags.

`platform = auto` detects the Docker engine architecture, which may differ from the host running Gradle. Explicit values are `linux/amd64` and `linux/arm64`.

The initial build or pull needs network access. Images stay in Docker's cache when the plugin removes runtime containers.

== Runtime files

Add `.aws-emulator/`, or your chosen `workingDirectory`, to the application's `.gitignore`. It contains generated local credentials while instances run. Managed and development runtime homes are isolated within this directory.

The plugin does not modify your personal AWS configuration. See xref:connections.adoc[credentials and TLS] for the host-side connection files and how consuming JVMs receive them.

== Resource task configuration

`runtimeName`, `mode`, and `apiCallTimeoutSeconds` belong to individual provisioning tasks. The defaults are `default`, `EmulatorMode.MANAGED`, and `30` seconds per SDK operation. Select another declared runtime with `runtimeName.set("integration")` or `--runtime integration`.

Each service guide lists its task properties. See xref:s3.adoc#task-properties[S3 task properties] for buckets and objects, or xref:sqs.adoc#task-properties[SQS task properties] for queues and message fixtures.
