= Spring Boot
include::_partials/attributes.adoc[]
:description: Run and debug Spring Boot applications with an AWS Emulator companion plugin.

The companion plugin `io.github.gregwhitaker.aws-emulator.spring-boot` adds `bootRunLocal` and `bootRunLocalDebug`. It automatically applies the base emulator plugin. Your application selects and applies `org.springframework.boot` and its Java or Kotlin JVM plugin.

The companion is a separate artifact, `io.github.gregwhitaker:gradle-aws-emulator-spring-boot`, released with the core plugin. It uses the application's Spring Boot task type and does not bring Spring Boot into your build transitively. Compatibility is tested with Spring Boot 3.5.16 and 4.1.2.

toc::[]

== Apply from a checkout

Use the xref:getting-started.adoc#apply-from-a-checkout[composite-build setup], then apply the companion:

[source,kotlin]
----
import io.github.gregwhitaker.awsemulator.aws.sqs.CreateSqsQueueTask

plugins {
    java
    id("org.springframework.boot") version "4.1.2"
    id("io.github.gregwhitaker.aws-emulator.spring-boot")
}

awsEmulator { port.set(0) }
springBootEmulator {
    profiles.set(listOf("local"))
    setupTasks.add("createApplicationQueue")
}
tasks.register<CreateSqsQueueTask>("createApplicationQueue") {
    mode.set(springBootEmulator.mode)
    queueName.set("application-events")
}
----

[source,groovy]
----
import io.github.gregwhitaker.awsemulator.aws.sqs.CreateSqsQueueTask

plugins {
    id 'java'
    id 'org.springframework.boot' version '4.1.2'
    id 'io.github.gregwhitaker.aws-emulator.spring-boot'
}

awsEmulator { port.set(0) }
springBootEmulator {
    profiles.set(['local'])
    setupTasks.add('createApplicationQueue')
}
tasks.register('createApplicationQueue', CreateSqsQueueTask) {
    mode.set(springBootEmulator.mode)
    queueName.set('application-events')
}
----

Plugin application order does not matter. Until both Spring Boot and Java are present, the companion exposes its settings and the base emulator tasks, without registering the Boot tasks or starting Docker.

== Run and debug

[source,shell]
----
./gradlew bootRunLocal
./gradlew bootRunLocal --args='--server.port=8081'
./gradlew bootRunLocalDebug
./gradlew stopAwsEmulator
----

The debug task listens on `127.0.0.1:5005` and waits for a debugger. The ordinary `bootRun` task is not connected to the emulator by applying this plugin.

Both local tasks use `BootRun`. They inherit `bootRun`'s main-class provider (including Spring Boot's automatic discovery), classpath, Java launcher, optimized-launch setting, working directory, environment, system properties, application arguments, JVM arguments, and argument providers when configured. Custom actions on `bootRun` are not copied. Configure the local task directly when it needs additional task behavior. Command-line `--args` overrides the copied application arguments.

The base plugin supplies endpoint, region, generated credentials, and TLS trust just before the JVM starts. Your application still declares its own AWS SDK dependencies. See xref:connections.adoc[Credentials and TLS] for connection details.

== Configuration

[cols="1,1,3",options="header"]
|===
|`springBootEmulator` property |Default |Behavior
|`mode` |`EmulatorMode.DEVELOPMENT` |Selects the persistent development instance or a build-owned `MANAGED` instance.
|`profiles` |`["local"]` |Adds `spring.profiles.active`; an empty list adds no profile argument.
|`jvmArgs` |`[]` |Additional JVM arguments for both local tasks.
|`setupTasks` |`[]` |Gradle task names or paths that both local tasks depend on.
|`debugPort` |`5005` |Debugger port, from 1 to 65535.
|`debugSuspend` |`true` |Whether the debug task waits for a debugger before starting the application.
|===

Resource setup tasks must select the same mode as the application. Wiring their `mode` to `springBootEmulator.mode`, as above, keeps them aligned. Use separate setup tasks for consumers that need different modes within one build. Applying the companion does not discover or run every resource task automatically.

Development instances retain their resources across Gradle invocations until `stopAwsEmulator` or `restartAwsEmulator`. For automatic cleanup after the application finishes, including ordinary application failures:

[source,kotlin]
----
import io.github.gregwhitaker.awsemulator.model.EmulatorMode

springBootEmulator { mode.set(EmulatorMode.MANAGED) }
----

Hard process termination or Docker daemon failure can prevent cleanup, as described in xref:testing.adoc[Tests and Java execution].

== Runnable example

The link:{repo-url}/tree/main/examples/spring-boot[Spring Boot example] sends and receives an SQS message and exits. From this repository:

[source,shell]
----
./gradlew -p examples/spring-boot bootRunLocal --configuration-cache
./gradlew -p examples/spring-boot bootRunLocal --configuration-cache
./gradlew -p examples/spring-boot stopAwsEmulator
----

Use `-Pmanaged=true` for automatic cleanup, or `bootRunLocalDebug` to attach a debugger. Browse the link:spring-boot-api/index.html[companion Java API] for the extension reference.
