= Getting started
include::_partials/attributes.adoc[]
:description: Apply the AWS Emulator Gradle plugin from a checkout and run the included integration example.

Start with Java 17+, Gradle 8.14+, and Docker running Linux containers. The first emulator run downloads and builds the pinned package; later runs reuse the image.

If an emulator is already running elsewhere, use xref:external-emulators.adoc[an external connection] instead; the Gradle machine then needs no Docker installation.

toc::[]

== Run the included example

From the plugin repository root:

[source,shell]
----
./gradlew -p examples/basic integrationTest --configuration-cache
----

The example creates S3 buckets, standard/FIFO SQS queues and a FIFO DLQ, publishes message fixtures, verifies object and message round trips and a signed STS request, then removes its managed container. Run the command a second time to exercise configuration-cache reuse.

No AWS account, AWS CLI, or personal AWS credentials are needed. The plugin supplies the emulator connection at task execution time.

== Apply from a checkout

Version {revnumber} is unpublished. Include the plugin repository in your application's plugin management instead of resolving a version from the Gradle Plugin Portal. Adjust the relative path for your checkout layout.

=== Kotlin DSL

.settings.gradle.kts
[source,kotlin]
----
pluginManagement {
    includeBuild("../gradle-aws-emulator")
}
----

.build.gradle.kts
[source,kotlin]
----
plugins {
    java
    id("io.github.gregwhitaker.aws-emulator")
}

awsEmulator {
    port.set(0)
    useWith(tasks.named<Test>("test"))
}
----

=== Groovy DSL

.settings.gradle
[source,groovy]
----
pluginManagement {
    includeBuild('../gradle-aws-emulator')
}
----

.build.gradle
[source,groovy]
----
plugins {
    id 'java'
    id 'io.github.gregwhitaker.aws-emulator'
}

awsEmulator {
    port.set(0)
    useWith(tasks.named('test'))
}
----

Add `.aws-emulator/` to the consuming application's `.gitignore`. It holds generated runtime files, including local emulator credentials while the instance runs.

Then run your application's `./gradlew test`. Tests with work run against a fresh managed emulator. A `NO-SOURCE` test task does not start one by itself. Your application must declare its own AWS SDK and test dependencies; the plugin's SDK dependencies support its provisioning tasks.

TIP: `port.set(0)` selects an available host port. Use it for parallel projects, concurrent builds, or simultaneous managed and development instances.

== Verify cleanup after failure

From the plugin repository root:

[source,shell]
----
./gradlew -p examples/basic integrationTest -PfailExample=true
----

This command is expected to fail its test. The managed container is still removed after the build's consumers finish.
