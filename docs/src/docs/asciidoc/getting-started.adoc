= Getting Started
include::_partials/attributes.adoc[]
:description: Get the AWS Emulator Gradle plugin from the Gradle Plugin Portal and run the included integration example.

Start with Java 17+, Gradle 8.14+, and Docker running Linux containers. The first emulator run downloads and builds the pinned package; later runs reuse the image.

If an emulator is already running elsewhere, use xref:external-emulators.adoc[an external connection] instead; the Gradle machine then needs no Docker installation.

toc::[]

== Apply From The Plugin Portal

Get the core plugin from the https://plugins.gradle.org/plugin/io.github.gregwhitaker.aws-emulator[Gradle Plugin Portal] and apply it with a version in your application's build script. Gradle uses the Portal by default, so no settings changes are needed for a standard build.

=== Kotlin DSL

.build.gradle.kts
[source,kotlin,subs="+attributes"]
----
plugins {
    java
    id("io.github.gregwhitaker.aws-emulator") version "{revnumber}"
}

awsEmulator {
    useWith(tasks.named<Test>("test"))
}
----

=== Groovy DSL

.build.gradle
[source,groovy,subs="+attributes"]
----
plugins {
    id 'java'
    id 'io.github.gregwhitaker.aws-emulator' version '{revnumber}'
}

awsEmulator {
    useWith(tasks.named('test'))
}
----

Add `.aws-emulator/` to the consuming application's `.gitignore`. It holds generated runtime files, including local emulator credentials while the instance runs.

Then run your application's `./gradlew test`. Tests with work run against a fresh managed emulator. A `NO-SOURCE` test task does not start one by itself. Your application must declare its own AWS SDK and test dependencies; the plugin's SDK dependencies support its provisioning tasks.

TIP: An available host port is selected automatically, supporting parallel projects, concurrent builds, and simultaneous managed and development instances. Use `-PawsEmulator.port=9297` when you need a fixed port.

For projects with separate unit and integration suites, attach the existing `integrationTest` task instead of `test`. The complete example below registers an integration suite and opts it in explicitly with `useWith`.

=== Custom Plugin Repositories

If your settings already declare `pluginManagement.repositories`, include `gradlePluginPortal()` alongside your other plugin repositories. This syntax works in both `settings.gradle.kts` and `settings.gradle`:

[source,kotlin]
----
pluginManagement {
    repositories {
        gradlePluginPortal()
    }
}
----

For Spring Boot applications, use the xref:spring-boot.adoc#apply-from-the-plugin-portal[companion plugin], which applies the core plugin automatically.

== Run The Included Example

From the plugin repository root:

[source,shell]
----
./gradlew -p examples/basic integrationTest --configuration-cache
----

The example creates S3 buckets, standard/FIFO SQS queues and a FIFO DLQ, publishes message fixtures, verifies object and message round trips and a signed STS request, then removes its managed container. Run the command a second time to exercise configuration-cache reuse.

No AWS account, AWS CLI, or personal AWS credentials are needed. The plugin supplies the emulator connection at task execution time. Repository examples use this checkout through composite builds so they exercise local plugin changes.

== Apply From A Checkout

To test local plugin changes in your own application, include the plugin repository in your application's plugin management. Adjust the relative path for your checkout layout.

.settings.gradle.kts
[source,kotlin]
----
pluginManagement {
    includeBuild("../gradle-aws-emulator")
}
----

.settings.gradle
[source,groovy]
----
pluginManagement {
    includeBuild('../gradle-aws-emulator')
}
----

Use the application build configuration above, omitting the version from the emulator plugin declaration. The same setup supplies the Spring Boot companion from the checkout; omit its version too, while keeping your application's Spring Boot plugin version.

== Verify Cleanup After Failure

From the plugin repository root:

[source,shell]
----
./gradlew -p examples/basic integrationTest -PfailExample=true
----

This command is expected to fail its test. The managed container is still removed after the build's consumers finish.

Next, follow a service guide such as xref:s3.adoc[S3] or xref:sqs.adoc[SQS] to provision the resources your application needs, or xref:lifecycle.adoc[start a persistent development instance].
