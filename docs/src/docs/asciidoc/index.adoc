== Try a working build

From this repository's root, run the included example:

.Terminal
[source,shell]
----
./gradlew -p examples/basic integrationTest --configuration-cache
----

It provisions S3 buckets and SQS queues, verifies signed SDK requests, and removes its container. The first run builds the emulator image; later runs reuse it. No AWS CLI or personal credentials are needed.

[[a-small-addition-to-your-build]]
== A small addition to your build

After xref:getting-started.adoc#apply-from-a-checkout[including the plugin checkout], connect your existing test task:

.build.gradle.kts
[source,kotlin]
----
plugins {
    java
    id("io.github.gregwhitaker.aws-emulator")
}

awsEmulator {
    port.set(0)
    useWith(tasks.named<Test>("test"))
}
----

Run `./gradlew test` in your application. The plugin supplies the endpoint, emulator credentials, and TLS trust when the task executes. Keep your application's AWS SDK and test dependencies; see xref:connections.adoc[SDK connection setup].

Applying the plugin alone does not start Docker. Your tasks opt in explicitly, and configuration-cache reuse is supported.

Both instances store resources in memory. Stopping or restarting discards those resources. Managed and development instances have separate containers and working directories. Custom resource tasks default to managed mode; module convenience tasks target development mode.

== Requirements

Use *Java 17+*, *Gradle 8.14+*, and a local *Docker engine running Linux containers*. The first run builds an image from AWS's pinned `1.0.322` package. Linux AMD64 and ARM64 are supported; subsequent runs reuse the image.

Docker integration is verified on Linux AMD64 and ARM64. Windows runs the Docker-free verification suite; Docker integration on Windows has not been verified.

This guide describes the plugin's current implementation. See https://github.com/aws/aws-emulator[AWS Emulator] for the upstream project, or xref:troubleshooting.adoc[troubleshooting] if something isn't working.
