== A small addition to your build

After xref:getting-started.adoc#apply-from-a-checkout[including the plugin checkout], opt your test task in:

.build.gradle.kts
[source,kotlin]
----
plugins {
    java
    id("io.github.gregwhitaker.aws-emulator")
}

awsEmulator {
    port.set(0)
    useWith(tasks.named<Test>("test"))
}
----

Applying the plugin registers tasks and configuration. Docker starts only when a lifecycle task, resource task, or opted-in consumer needs an emulator.

== Choose the right lifetime

[cols="1,2,2",options="header"]
|===
| |Managed instance |Development instance
|Start with |`awsEmulator.useWith(...)` or a custom resource task |`startAwsEmulator`, a module convenience task, or a resource task with `DEVELOPMENT` mode
|Lifetime |Shared by participating tasks in one project, within the build |Survives the Gradle invocation
|Cleanup |Automatic after consumers finish, including ordinary task failures |Explicit `stopAwsEmulator`
|Best for |Tests and Gradle-launched Java applications |Interactive local development
|===

Both instances keep AWS resources in memory. Stop or restart discards those resources. Managed and development instances use separate container names and working directories.

== Requirements

The plugin requires Java 17+, Gradle 8.14+, and a local Docker engine running Linux containers. It builds an image from AWS's pinned `1.0.322` package on first use. Linux AMD64 and ARM64 are supported; later runs reuse the image.

Docker integration is verified on Linux AMD64 and ARM64. Windows runs the Docker-free verification suite; Docker integration on Windows has not been verified.

This guide describes the plugin's current implementation. See https://github.com/aws/aws-emulator[AWS Emulator] for the upstream emulator project.
