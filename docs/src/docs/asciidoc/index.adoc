[.home-example]
--
[[a-small-addition-to-your-build]]
.build.gradle.kts
[source,kotlin]
----
plugins {
    java
    id("io.github.gregwhitaker.aws-emulator")
}

awsEmulator {
    useWith(tasks.named<Test>("test"))
}
----
--

== Run the example

From this repository's root, run the included example:

[.quickstart-command]
--
.Terminal
[source,shell]
----
./gradlew -p examples/basic integrationTest --configuration-cache
----
--

<div class="runtime-flow" aria-label="What the example does">

The first run builds the emulator image; later runs reuse it. Run the command again to check configuration-cache reuse. Follow the xref:getting-started.adoc[getting started guide] to add the plugin to your own application.

[[choose-the-right-lifetime]]
== Runtime modes

Use a managed instance for build tasks or a persistent development instance for local applications.

++++
<div class="lifecycle-grid">
  <a href="testing.html" class="lifecycle-card">
    <span class="card-eyebrow">01 / TESTS &amp; BUILD TASKS</span>
    <strong>Managed instance <span aria-hidden="true">↗</span></strong>
    <p>A managed instance shared by participating tasks. Starts when needed and cleans up when they finish, including ordinary task failures.</p>
    <code>awsEmulator.useWith(…)</code>
    <span class="card-link">Test integration <span aria-hidden="true">→</span></span>
  </a>
  <a href="lifecycle.html" class="lifecycle-card">
    <span class="card-eyebrow">02 / LOCAL DEVELOPMENT</span>
    <strong>Development instance <span aria-hidden="true">↗</span></strong>
    <p>A development instance that stays running between builds. It survives Gradle and application exits until you explicitly stop it.</p>
    <code>./gradlew startAwsEmulator</code>
    <span class="card-link">Lifecycle tasks <span aria-hidden="true">→</span></span>
  </a>
</div>
++++

Managed and development instances use separate containers and working directories. Both store resources in memory, so stopping or restarting discards them. Custom resource tasks default to managed mode; module convenience tasks target development mode.

xref:external-emulators.adoc[External connections] use an existing emulator's endpoint, credentials, and CA certificate.

== Requirements

Use *Java 17+*, *Gradle 8.14+*, and a local *Docker engine running Linux containers*. The first run builds an image from AWS's pinned `1.0.322` package. Linux AMD64 and ARM64 are supported; subsequent runs reuse the image.

Docker integration is verified on Linux AMD64 and ARM64. Windows runs the Docker-free verification suite; Docker integration on Windows has not been verified.

For ports, images, regions, and timeouts, see xref:configuration.adoc[configuration]. See https://github.com/aws/aws-emulator[AWS Emulator] for the upstream project, or xref:troubleshooting.adoc[troubleshooting] if something isn't working.
