= Ktor
include::_partials/attributes.adoc[]
:description: Run and test Ktor applications against AWS Emulator using the core Gradle plugin.

Ktor uses the core `io.github.gregwhitaker.aws-emulator` plugin. Attach its existing Gradle `run` and `test` tasks with `awsEmulator.useWith(...)`; no additional emulator companion is required. Your application chooses its framework and AWS SDK versions.

The example uses Java 17+, Gradle 8.14+, a local Docker engine with Linux containers, and AWS SDK for Java v2. It performs signed HTTPS requests with normal certificate and hostname validation. No AWS account or AWS CLI is required.

toc::[]

== Run The Example

From the repository root:

[source,shell]
----
./gradlew -p examples/ktor test run --configuration-cache
./gradlew -p examples/ktor test run --configuration-cache
----

The example build provisions an SQS queue before the framework consumers start. Tests and application execution share a fresh managed instance within that project and build. The repeated command reuses the configuration cache while provisioning and consumers execute again. The managed container, generated credentials, and trust stores are removed after the consumers finish, including ordinary failures.

The example is an independent composite build. `classes testClasses` compiles it without Docker; `test`, `run`, and `build` require Docker. Applying the plugin or running `help` does not start an emulator.

== Application And Test Integration

The Kotlin example applies the Kotlin JVM and Ktor Gradle plugins. Its main function starts a Netty server on a loopback port, requests `/message`, verifies the SQS round trip, and stops the server. Its JUnit 5 test uses https://ktor.io/docs/server-testing.html[Ktor's `testApplication` engine] to exercise the same route against the emulator.

The application creates an AWS SDK for Java v2 client using the normal endpoint, region, credential, and TLS settings. Blocking SDK calls run on `Dispatchers.IO`; the client closes when the application stops. Ktor does not need an AWS-specific configuration adapter for this setup.

== Development, Debugging, And Failures

The example accepts `-Pdevelopment=true` for application runs:

[source,shell]
----
./gradlew -p examples/ktor run -Pdevelopment=true --configuration-cache
./gradlew -p examples/ktor run -Pdevelopment=true --configuration-cache
./gradlew -p examples/ktor listSqsQueues
./gradlew -p examples/ktor stopAwsEmulator
----

The application still exits after its round trip. Its development emulator survives success or failure and is reused until explicitly stopped. `test` always uses a managed instance, even with `-Pdevelopment=true`. The example registers separate setup tasks so managed tests and development runs cannot accidentally target the same runtime.

To debug the example, run `run --debug-jvm` and attach to port 5005. Gradle suspends the JVM until a debugger connects. The emulator and queue are ready before the application JVM starts.

To exercise managed cleanup after application or test failure:

[source,shell]
----
./gradlew -p examples/ktor run -PfailExample=true
./gradlew -p examples/ktor test -PfailExample=true
----

These commands intentionally fail after completing their SDK round trip.

== Compatibility And Verification

[cols="1,2,2",options="header"]
|===
|Framework |Docker-free compatibility fixtures |Real-emulator fixtures
|Ktor |3.5.2 and 3.6.1; Kotlin 2.4.21 |Ktor 3.6.1
|===

The Docker-free suite compiles the application and its tests, verifies setup ordering and runtime selection, and checks configuration-cache reuse without invoking Docker. It runs under the repository's JDK/Gradle CI matrix. Override the example framework version with `-PktorVersion=3.5.2` to reproduce the alternate fixture.

The real-emulator suite checks framework consumers, signed HTTPS, inherited credential/endpoint replacement, managed runtime sharing and failure cleanup, development reuse, and isolation between development runs and managed tests. Both suites copy the runnable example, so the documented sources are the compatibility fixture.

[source,shell]
----
./gradlew :plugin:functionalTest --tests '*FrameworkCompatibilityFunctionalTest'
./gradlew :plugin:integrationTest --tests '*FrameworkIntegrationTest'
----

Verified support covers JVM `run` and `Test` consumers using AWS SDK for Java v2. Native images, Kotlin multiplatform or AWS SDK for Kotlin, and continuous restart or automatic reload workflows are outside this compatibility scope. IDE launches must delegate to the opted-in Gradle task to receive the generated connection. See xref:connections.adoc[Credentials & TLS] for client-level overrides and trust configuration.
