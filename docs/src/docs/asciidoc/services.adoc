= Configuration, events, streams, keys, and logs
include::_partials/attributes.adoc[]

Provision Parameter Store, Secrets Manager, EventBridge, Kinesis Data Streams, KMS, and CloudWatch Logs resources before application tests. These task types share the xref:resources.adoc[S3/SQS resource task] lifecycle, connection settings, and timeout behavior.

For authentication resources and signed JWT application tests, see xref:cognito.adoc[Cognito User Pools].

toc::[]

== Run the complete example

[source,shell]
----
./gradlew -p examples/services verifyServices --configuration-cache
./gradlew -p examples/services verifyServices --configuration-cache
----

The example provisions all six services, reads configuration and secrets with AWS SDK for Java v2, routes a matching EventBridge event to SQS, consumes Kinesis records, encrypts/decrypts a file, and retrieves application logs. The second invocation exercises configuration-cache reuse against a fresh managed emulator. `-PfailExample=true` deliberately fails the application test to demonstrate managed cleanup.

Custom tasks default to `MANAGED`. Predefined inspection/deletion commands default to `DEVELOPMENT`; `--mode=MANAGED` changes this for a single command. Resource tasks always execute and are not build-cacheable. Applying the plugin and listing tasks do not start Docker. Task input values may be stored in Gradle's configuration cache; fixtures should contain local test values.

For persistent development resources:

[source,shell]
----
./gradlew -p examples/services provisionServices -Pdevelopment=true
./gradlew -p examples/services listSsmParameters listSecrets listEventBuses listKinesisStreams listKmsKeys listLogGroups
./gradlew -p examples/services stopAwsEmulator
----

`-Pdevelopment=true` is an example-specific switch for provisioning and inspection. Run `verifyServices` in its default managed mode, so application tests and resource tasks use the same instance.

== Parameter Store and Secrets Manager

Task packages are `io.github.gregwhitaker.awsemulator.aws.ssm` and `io.github.gregwhitaker.awsemulator.aws.secretsmanager`.

[cols="1,2",options="header"]
|===
|Task type |Configuration
|`PutSsmParameterTask` |`parameterName`, `value`, `type` (default `String`), optional `keyId`, `overwrite` (default `false`)
|`PutSsmParametersTask` |`fixtures` JSON file, `overwrite`
|`ListSsmParametersTask` |Lists parameter names, without values
|`DeleteSsmParametersTask` |Explicit `names` list
|`PutSecretTask` |`secretName`, `value` string, optional `keyId`, `overwrite` (default `false`)
|`PutSecretsTask` |`fixtures` JSON file, `overwrite`
|`ListSecretsTask` |Lists secret names, including secrets scheduled for deletion
|`DescribeSecretTask` |`secretName`; prints ARN and deletion date without the value
|`DeleteSecretsTask` |Explicit `names`, `recoveryWindowInDays` (7–30; default 30), `force` (default `false`)
|===

Kotlin DSL:

[source,kotlin]
----
import io.github.gregwhitaker.awsemulator.aws.ssm.PutSsmParametersTask
import io.github.gregwhitaker.awsemulator.aws.secretsmanager.PutSecretsTask

val parameters = tasks.register<PutSsmParametersTask>("seedParameters") {
    fixtures.set(layout.projectDirectory.file("fixtures/parameters.json"))
}
val secrets = tasks.register<PutSecretsTask>("seedSecrets") {
    fixtures.set(layout.projectDirectory.file("fixtures/secrets.json"))
}
val tests = tasks.named<Test>("test") { dependsOn(parameters, secrets) }
awsEmulator { port.set(0); useWith(tests) }
----

Groovy DSL:

[source,groovy]
----
import io.github.gregwhitaker.awsemulator.aws.ssm.PutSsmParametersTask
import io.github.gregwhitaker.awsemulator.aws.secretsmanager.PutSecretsTask

def parameters = tasks.register('seedParameters', PutSsmParametersTask) {
    fixtures.set(layout.projectDirectory.file('fixtures/parameters.json'))
}
def secrets = tasks.register('seedSecrets', PutSecretsTask) {
    fixtures.set(layout.projectDirectory.file('fixtures/secrets.json'))
}
def tests = tasks.named('test') { dependsOn(parameters, secrets) }
awsEmulator { port.set(0); useWith(tests) }
----

.Parameter fixtures
[source,json]
----
[
  {"name":"/app/url","value":"http://localhost:8080"},
  {"name":"/app/features","value":"catalog,checkout","type":"StringList"},
  {"name":"/app/token","value":"local-token","type":"SecureString"}
]
----

.Secret fixtures
[source,json]
----
[
  {"name":"app/database","value":"{\"username\":\"local\",\"password\":\"local-only\"}"}
]
----

Every entry requires string `name` and `value`. Parameters additionally accept `type` (`String`, `StringList`, or `SecureString`, default `String`). Both schemas accept optional `keyId`; for parameters it requires `SecureString`. Set an explicit task dependency on `CreateKmsKeyTask` when referring to a custom key alias. Parameter values use the Standard tier, with a 4096-byte maximum; secret strings allow up to 65536 UTF-8 bytes. Binary secrets, parameter policies, secret rotation, and version-stage management are outside these task types.

Fixtures must be nonempty JSON arrays no larger than 16 MiB. Unknown fields, duplicate JSON keys, duplicate resource names, malformed JSON, and invalid entries fail before starting Docker. All entries are validated before provisioning; service calls then run sequentially. A service failure reports the failing name and number of completed entries. Earlier changes remain in a development instance. No automatic rollback is attempted.

Identical values are reused without creating new versions. Different values require `overwrite=true`. Changing a parameter's type requires explicit deletion and recreation. Explicit key identifiers are compared with the identifier reported by the service; consistently use the same key ID or alias. Provisioning never restores a secret scheduled for deletion. Metadata commands and provisioning errors omit values; applications read values through their SDKs.

Predefined commands: `listSsmParameters`, `deleteSsmParameters`, `listSecrets`, `describeSecret`, and `deleteSecrets`. Pass selected names with repeated `--names` options. Secret deletion defaults to a recovery window; `--force` requests asynchronous deletion without recovery. Stopping a managed emulator discards its entire in-memory state immediately.

== EventBridge

Package: `io.github.gregwhitaker.awsemulator.aws.eventbridge`.

[cols="1,2",options="header"]
|===
|Task type |Configuration
|`CreateEventBusTask` |`eventBusName`; reuses an existing bus
|`PutEventBridgeRuleTask` |`eventBusName`, `ruleName`, JSON `eventPattern`, `overwrite` (default `false`); creates an enabled rule
|`PutEventBridgeSqsTargetTask` |`eventBusName`, `ruleName`, `queueName`, `targetId`, `overwrite`; resolves a standard queue and grants this rule permission to send messages
|`PutEventBridgeTargetsTask` |`eventBusName`, `ruleName`, `targets` map of target IDs to standard SQS ARNs, `overwrite`; queue policies must be configured separately
|`PublishEventBridgeEventsTask` |`eventBusName`, `fixtures` JSON file
|`ListEventBusesTask` |Lists buses and ARNs
|`ListEventBridgeRulesTask` |`eventBusName`; lists rules and their targets
|`DeleteEventBridgeRuleTask` |`eventBusName`, `ruleName`; removes the rule's targets, then the rule
|`DeleteEventBusTask` |`eventBusName`; requires explicit deletion of its rules first
|===

.Event fixtures
[source,json]
----
[
  {"source":"app.orders","detailType":"OrderCreated","detail":{"id":"order-1"}}
]
----

`source` and `detailType` are nonblank strings; `detail` must be a JSON object. This release uses a conservative 256 KiB entry/request limit and batches up to ten events. It verifies bus existence before publishing. Partial batch failures identify one-based fixture indexes; successful events are retained and are not automatically replayed. Rerunning a publisher can duplicate events.

Target IDs make repeated setup stable. Existing conflicting targets/rules require `overwrite=true`; unrelated target IDs are preserved. The SQS convenience task preserves unrelated queue-policy statements and adds one rule-scoped grant. Deleting a rule leaves that grant in the queue policy; it does not delete the queue. FIFO targets, schedules, SNS targets, input transformations, and replay/archive management are not part of this initial task scope.

Declare cleanup ordering explicitly when deleting dependent resources in one build. Configuration-cache execution can run independent tasks concurrently: use `deleteEventBus.mustRunAfter(deleteEventBridgeRule)` when both commands are selected, and similarly order log-stream deletion before log-group deletion. The runnable example configures these ordering constraints.

Predefined commands: `listEventBuses`, `listEventBridgeRules`, `deleteEventBridgeRule`, and `deleteEventBus`. Rule commands accept `--eventBusName` and `--ruleName` as applicable. The default event bus cannot be deleted.

== Kinesis Data Streams

Package: `io.github.gregwhitaker.awsemulator.aws.kinesis`.

* `CreateKinesisStreamTask`: `streamName`, `shardCount` (default 1), `waitTimeoutSeconds` (default 60). Creates/reuses a provisioned stream and waits for `ACTIVE`; conflicting shard counts or stream modes fail.
* `PublishKinesisRecordsTask`: `streamName`, `fixtures`. Sends UTF-8 strings with partition keys through `PutRecords`.
* `ListKinesisStreamsTask`: lists all stream names.
* `DeleteKinesisStreamTask`: `streamName`, `waitTimeoutSeconds` (default 60). Waits for disappearance; missing streams are safe to repeat.

.Record fixtures
[source,json]
----
[
  {"partitionKey":"order-1","data":"first-record"},
  {"partitionKey":"order-2","data":"second-record"}
]
----

Both fields must be strings, and partition keys must be nonblank with at most 256 characters. This release conservatively limits each record, including its partition key, to 1 MiB and each batch to 500 records/5 MiB. Partial failures report one-based fixture indexes without replaying successful records. `PutRecords` does not guarantee ordering. Resharding, retention changes, and enhanced fan-out consumers are outside this scope.

The pinned SDK defaults to CBOR, which this emulator workflow does not accept. Kinesis tasks therefore use a process-isolated Gradle worker with `aws.cborEnabled=false`; no Gradle daemon system property is changed. `awsEmulator.useWith(...)` sets `aws.cborEnabled=false` and `CBOR_ENABLED=false` for participating application JVMs. Configure JSON explicitly for separately launched SDK consumers.

Predefined commands: `listKinesisStreams` and `deleteKinesisStream --streamName=...`.

== KMS

Package: `io.github.gregwhitaker.awsemulator.aws.kms`.

* `CreateKmsKeyTask`: `aliasName`. Creates/reuses an enabled `SYMMETRIC_DEFAULT` encryption key. The alias makes repeated setup stable.
* `CreateKmsAliasTask`: `aliasName`, `keyId`, `overwrite` (default `false`). Changing an existing alias's target requires explicit overwrite.
* `ListKmsKeysTask`: lists key IDs and ARNs.
* `DeleteKmsAliasTask`: `aliasName`; does not delete its key.
* `ScheduleKmsKeyDeletionTask`: `keyId`, `pendingWindowInDays` (7–30; default 30). Already-pending keys are left alone. This is scheduled deletion, not immediate deletion.
* `EncryptKmsFileTask` and `DecryptKmsFileTask`: `keyId`, `inputFile`, `outputFile`, optional `encryptionContext` map (default empty). Use the same context for encryption and decryption.

Encryption accepts up to 4096 plaintext bytes. Decryption accepts up to 6144 ciphertext bytes. Files are binary, not Base64 strings. Input and output must differ. Result files are replaced atomically when supported and use owner-only permissions on POSIX filesystems. Bodies are not printed. A managed key disappears when its emulator stops, so both tasks must share that runtime; the runnable example wires the decrypt input to the encrypt task's output provider.

Predefined commands: `listKmsKeys`, `deleteKmsAlias --aliasName=...`, and `scheduleKmsKeyDeletion --keyId=...`. Managed aliases starting with `alias/aws/` are reserved. Asymmetric keys, signing, imported key material, grants, and policy enforcement testing are outside this scope.

== CloudWatch Logs

Package: `io.github.gregwhitaker.awsemulator.aws.cloudwatchlogs`.

* `CreateLogGroupTask` / `DeleteLogGroupTask`: `logGroupName`.
* `CreateLogStreamTask` / `DeleteLogStreamTask`: `logGroupName`, `logStreamName`. Create the group first using `dependsOn`.
* `ListLogGroupsTask`: lists group names.
* `GetLogEventsTask`: `logGroupName`, `logStreamName`, `outputFile`, optional `startTime` in epoch milliseconds, `maxEvents` (default 10000).
* `FilterLogEventsTask`: `logGroupName`, `outputFile`, `filterPattern` (default empty), optional `startTime`, `maxEvents`, `minimumEvents` (default 0), `waitTimeoutSeconds` (default 30).

Read tasks follow pagination and write JSON arrays without printing message bodies. `GetLogEventsTask` terminates when the forward token stops advancing. `FilterLogEventsTask` optionally polls until at least `minimumEvents` match; each poll replaces its snapshot rather than appending duplicates. Exceeding `maxEvents` fails rather than silently truncating. Raise the limit (maximum 1000000) or narrow the query. SDK calls retain the shared `apiCallTimeoutSeconds` deadline, including when a polling deadline expires during a call.

Predefined commands: `listLogGroups`, `deleteLogGroup --logGroupName=...`, and `deleteLogStream --logGroupName=... --logStreamName=...`. Log retention policies, subscriptions, Logs Insights, metrics, and alarms are outside this initial scope.

== Verified scope

The examples exercise these workflows against the pinned AWS Emulator `1.0.322`, using AWS SDK for Java v2 `2.39.6`. They establish the behavior used by these tasks, not complete AWS service equivalence. https://docs.aws.amazon.com/emulator/latest/userguide/fidelity.html[AWS Emulator fidelity] varies by operation and release. Step Functions, Lambda, and API Gateway tasks remain future work.
